# Thumb MCP Design

The server makes thumbnails: a file in, a small picture out, for a person who may read that file, in Lore or
Artifact. It knows nothing of what a caller does with one. It holds no App and lists nothing.

It reads as the person who asked, through the Hub and Artifact's client, so a file's owner decides every read. It keeps
no record of anybody, and nothing it keeps answers anybody by itself.

## Service Identity

```text
repository   veoveo-mcp-thumb
slug         thumb
URI scheme   thumb
permission   thumb.thumbnails.read
MCP          /thumb/mcp
liveness     /livez
readiness    /readyz
port         8807
```

## Standards And Protocols

| Standard or protocol | Implemented profile |
|---|---|
| [Model Context Protocol](https://modelcontextprotocol.io/specification/) | Version `2026-07-28`, JSON-RPC 2.0 over Streamable HTTP, under the hosted MCP contract, through the SDK. |
| [MCP Skills extension](https://github.com/modelcontextprotocol/ext-skills) | The skill `make-thumbnails`. |
| [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12/) | Tool inputs and results, generated by Schemars from the contract's types. |
| [JWT access tokens RFC 9068](https://www.rfc-editor.org/rfc/rfc9068.html) | The Hub forwards each request with an access token that names the caller, the caller's tenant and the permissions it grants. |
| [HTTP range requests, RFC 9110 §14](https://www.rfc-editor.org/rfc/rfc9110#name-range-requests) | A file's first byte to learn its content address and length, and a video's two ends. |
| [WebP](https://developers.google.com/speed/webp) | The pictures this server draws. A stage's, from USD, are JPEG. |
| [Landlock](https://docs.kernel.org/userspace-api/landlock.html) ABI 4 | A renderer's narrower sandbox. |

## Domain Contract

| Kind | Name | Permission | Answer |
|---|---|---|---|
| Tool | `thumbnail` | `thumb.thumbnails.read` | `Thumbnail`: a picture of `source` at `size`, with its media type, in base64, or nothing when one cannot be made |

`source` is `{from: "lore", repository, branch, path}` or `{from: "artifact", artifact}`. `size` is `small`,
at most 480 pixels on a side, or `large`, at most 1280. A refused file is an error; a file that cannot be
drawn is an empty answer, which a caller can show as it likes.

A server's App reaches a thumbnail through a tool of its own server, which calls this one as the same person, since a view
reads only its own server.

## A Thumbnail

A thumbnail is one small image of one file's content. Drawn once, it is the same for everybody who may read
that content, so it is kept by that content, and nothing has to be told when a file changes:

| File | Kept by |
|---|---|
| In Lore | Its content address, the Hub's `ETag` |
| In Artifact | Its identifier, since an artifact never changes |

Seeing a thumbnail is reading the file. So every call first asks the owner, as the person: a read of the file's
first byte in Lore, `ReadArtifact` in Artifact. A refusal ends the call, whatever is kept. A removed grant ends
a person's thumbnails on their next request, and an address a person guesses reaches nothing without a file they
may read that has it.

A first call for a content draws it while the caller waits. Calls for one content wait for one draw, and three
draw at once. Thumbnails are kept under `VEOVEO_THUMBNAIL_DIRECTORY`, `/sandbox/state/thumbnails` on the factory's
persistent disk. They are never removed, because each is small and any can be drawn again. A file that could not
be drawn is not tried again for an hour, so a broken file costs one attempt per hour, not one per request.

Before reading anything the server knows which recipe a file's name or media type takes, so a file with none
is read no further.

## Recipes

Each recipe is a command line of a standard program, the ones [Thumbelina](https://hub.docker.com/r/sciactive/thumbelina)
(Apache-2.0) runs, except for 3D. It is a recipe here and not a service because a job needs what its server does not
have: a time limit, a process group to end, and a folder and limits of its own. Each recipe leaves `page.png`, at most
1280 pixels on a side, and one last `convert` makes both sizes.

| File | Program |
|---|---|
| `doc`, `docx`, `odt`, `rtf`, `xls`, `xlsx`, `ods`, `csv`, `tsv`, `ppt`, `pptx`, `odp`, `html`, `htm`, `xhtml` | `soffice` to a PDF of the first page, then `pdftoppm` |
| Text and code | The same, as `input.txt`, so that it shows as what it is |
| `pdf` | `pdftoppm`, first page |
| Images and `psd` | `convert`, first frame or layer |
| `svg` | `rsvg-convert` |
| Video | `ffmpeg`, a representative frame from a second in |
| Audio | `ffmpeg`, its cover, or the shape of its first five minutes |
| glTF binary, FBX, OBJ, STL, PLY, Collada, 3DS, STEP, IGES, BREP, 3MF, DXF, Alembic, VRML, IFC, Draco | `f3d` on the GPU, through EGL |
| USD | The USD server's `thumbnail`, which draws on the GPU and keeps its own |

HTML is drawn by LibreOffice, which runs none of its scripts. An artifact that is a USD stage has no thumbnail, since the USD
server reads stages from Lore. A DWG has none, because no program here reads one. A `gltf` file whose buffers are separate files
has none either, since a job holds one file.

Debian's `f3d` has no EGL, so the image installs F3D's own release, pinned by checksum, under `/usr`, which the factory's policy
lets a sandbox read. Its USD plugin is not used.

### What Is Read

A video or a sound larger than 48 MiB is not read whole: its first 32 MiB and last 16 MiB go at their places in a file of its
full length with nothing between, which holds what a frame needs, wherever a container keeps its index. Any other file is read
whole, up to 2 GiB; a larger one has no thumbnail.

## Confinement

A renderer parses a stranger's file, so assume it can be made to run anything. The factory's sandbox lets every program reach
the internet and lets the server's user read the sandbox's disk, including the server's registration key. So each step runs
through this program's `confine` subcommand, which limits itself with Landlock, needing no privilege, and then becomes the renderer:

| Limit | What it keeps from a renderer |
|---|---|
| Reads only the system's programs, libraries and configuration, and writes only its job's folder. LibreOffice also writes `/tmp`, where it puts its one pipe whatever it is told; nothing of the server's is there, and only one LibreOffice runs at a time, so that no two can reach each other through it | The server's key, other jobs and every kept thumbnail |
| Opens no TCP connection and listens on no port | The internet, the Hub, the file's way out |
| Landlock's own rule on tracing a less limited process | The server's memory and environment, through `/proc` too |
| A process group of its own, ended when the step does | What it leaves running |
| A time limit: 90 seconds for a document, 60 for any other step | The server's capacity |
| 6 GiB of address space, unless it draws on the GPU, whose driver maps more | The sandbox's memory |
| An empty environment but `PATH`, `HOME`, `TMPDIR`, `MAGICK_TMPDIR` and `LANG`, and the GPU's two variables for `f3d` | Anything the server was started with |

`confine` refuses to start the renderer when any limit cannot be applied, so a kernel without Landlock's network rules makes no
thumbnails rather than unconfined ones. A job's input is named by the server, `input.{extension}` with a checked extension, so that
no program reads a person's file name as an option or a format's prefix.

A caller only ever receives a picture this server re-encoded, never the file, so nothing in a file can run in an App that shows it.

## Architecture

```text
contract/    names, the tool's request and answer, permission, addresses
hub.rs       reading a file through the Hub, for one caller
thumbnail.rs a thumbnail: asking the owner, what is kept, one draw of a content at a time
render.rs    the recipes and their steps
confine.rs   the `confine` subcommand
mcp/         the route table, the skill and the documents
server/      configuration, registration and startup
```

The `contract` feature builds without a runtime dependency. Consumers call `thumbnail` through it, and it depends on no other
server's contract.

## Factory

`openshell/image/` holds the toolchain and the programs. It opts in to the GPU as any factory repository does. `openshell/run`
builds and starts the server. It adds no network rule and no provider: the base policy's rules for the Hub, Lore's files and
Artifact's signed URLs are all it uses.

## Persistence

No tables. Under `/sandbox/state`: the registration's `keys/`, the kept `thumbnails/` and the jobs' `work/`, which starts empty.
